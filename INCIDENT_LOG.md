# Enclave Compliance — Incident Log

Every security incident — reported externally, self-discovered, or surfaced by CI — affecting Enclave-GAP, Enclave-SSP, Enclave-AI, or this website, per `ENCLAVE_COMPLIANCE_INCIDENT_RESPONSE_PLAN.md` (IR-5). Logged at the time of confirmation, not reconstructed after the fact.

| Date | Product | Description | Severity | Status | Resolution |
|---|---|---|---|---|---|
| 2026-08-23 | Enclave-SSP | Cross-process race on the credential keyfile — the in-process mutex gave no real protection, causing an actual credential loss during development. | High | Resolved | Real OS-level advisory file lock added (`crypto::lock_keyfile`/`KeyfileGuard`) across every read-modify-write call site; regression test added. See `ENCLAVE_SSP_THREAT_MODEL.md` (SV-222567). |
| 2026-08-17 | Enclave-GAP | `cargo audit` flagged RUSTSEC-2026-0187, a high-severity (7.5) stack-overflow advisory in `lopdf`, transitively pulled in via `pdf-extract` (used for policy-document text extraction). | High | Resolved | `pdf-extract` pinned to a patched `0.12` line. See `cargo_audit_log.md` in the Enclave-GAP repository. |
| 2026-09-14 | Enclave-SSP | The frontend's `ErrorBoundary` (the crash-recovery screen shown on an unexpected error) rendered the raw JavaScript error and full stack trace directly on screen, for any user of any role, including a not-yet-authenticated one — an information-disclosure gap on the frontend-crash path, distinct from the backend's own `errors::sanitize` boundary. Found during a cross-product error-handling review, not reported externally. | Medium | Resolved | `ErrorBoundary.jsx` now shows a fixed, generic message; the real error still reaches the developer console via `componentDidCatch`, unreachable to an ordinary user in a packaged build. Live-verified with a forced test crash. Ported (already fixed) to Enclave-AI and Enclave-GAP the same day, neither of which had a crash-recovery screen at all until this port. |
| 2026-09-14 | Enclave-AI | A backend PDF-report chart-rendering path (`reports.rs`) returned a raw, unformatted internal error string on a corrupt-chart-image failure, bypassing the standard `errors::sanitize` boundary the rest of the application enforces. Narrow reachability — requires the application's own internally rendered chart image to fail decoding. Found during the same cross-product review. | Low | Resolved | Routed through `errors::sanitize` like every other error path in the application. |

All incidents above were caught during development, before the affected code reached a customer — no customer notification was required under IR-6 at the time. New rows should follow the same format and cite the source document with the full technical detail rather than duplicating it here.
